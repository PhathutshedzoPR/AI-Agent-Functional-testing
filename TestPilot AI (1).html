Bug Reports

3 defects found
BUG-001
Login accepts invalid credentials — no error displayed
Critical P1
Authentication Defect Confidence: 97% Feature: Login
Steps to Reproduce: 1. Navigate to /login · 2. Enter username: invalid@user.com · 3. Enter password: wrongpassword · 4. Click Login
Expected: Authentication rejected — error message displayed ("Invalid username or password")
Actual: User redirected to /dashboard — no rejection, no error
Root Cause: Server-side authentication validation likely returning 200 for all credential attempts. Backend auth service may not be connected in current deployment.
Recommended Fix: Verify authentication middleware is active. Ensure POST /api/auth/login returns 401 for invalid credentials. Validate response handling in frontend auth interceptor.
Evidence
Screenshot captured URL: /dashboard (expected: /login) TC-002 • 2026-10-05 12:31:23
BUG-002
Checkout payment redirect results in 502 Bad Gateway
Critical P1
API Defect Confidence: 99% Feature: Checkout
Steps to Reproduce: 1. Add item to cart · 2. Proceed to checkout · 3. Fill valid billing details · 4. Enter card: 4242 4242 4242 4242 · 5. Click "Place Order"
Expected: Order confirmation page with order number (ORD-XXXXXX)
Actual: HTTP 502 Bad Gateway error — payment gateway unreachable. Console: "ERR_NAME_NOT_RESOLVED pay.demostore.internal"
Root Cause: Payment gateway service endpoint (pay.demostore.internal) is not reachable. DNS resolution failure suggests the internal payment service is down or misconfigured in this environment.
Recommended Fix: Verify payment gateway service is deployed and DNS entry pay.demostore.internal resolves correctly. Add payment service health check to deployment pipeline.
BUG-003
Promo code input accepts invalid codes without error message
High P2
Validation Defect Confidence: 88% Feature: Cart
Steps to Reproduce: 1. Add item to cart · 2. Open cart page · 3. Enter promo code: INVALID123 · 4. Click "Apply"
Expected: Error message: "Promo code INVALID123 is not valid"
Actual: Button returns to default state with no feedback — no success, no error, no visual change
Root Cause: Promo code validation API returns 400 but the frontend error handler silently swallows the response without surfacing a UI notification.
Recommended Fix: Add error toast notification to the promo code "Apply" handler. Display validation message from API response body.

Our Recommendations

Based on TestPilot AI best practices
Must Do Every project
Always test authentication before anything else
Auth failures are the highest-impact defect type. Run login, logout, session expiry, and invalid-credential tests as your P1 gate — if auth is broken, every downstream test is unreliable. TestPilot automatically prioritises TC-00x auth flows first.
🔒 Security + Functional
Must Do APIs & web apps
Test your API endpoints directly, not just through the UI
UI tests can pass while the API silently accepts bad data or skips auth. Use the REST/GraphQL API target to test every endpoint independently — check that unauthenticated requests return 401, that schema validation rejects bad payloads, and that error messages don't leak stack traces.
⚡ REST API Target
High Value Mobile projects
Decompile and audit your APK before publishing
Android apps frequently ship with hardcoded API keys, overly broad permissions, and exported Activities that allow deep-link abuse. Run the APK target on every release build to catch permission creep, insecure data storage, and intent vulnerabilities before they reach the Play Store.
📱 APK Target
High Value All codebases
Let Gemini generate unit tests for your functions
Upload your source file or GitHub URL and let Gemini read the function signatures and logic. It will write test cases covering the happy path, boundary values, nulls, and error branches you probably didn't think of. Especially useful for utility functions and data-processing code.
🔬 Code Target + Gemini API
High Value Any release
Run an OWASP Top-10 scan before every go-live
SQL injection, XSS, and broken auth are the most common vulnerabilities in student and early-stage projects — and the easiest to miss in manual testing. The Security Scan target checks all 10 OWASP categories automatically, gives a CVSSv3 score per finding, and suggests the exact code fix.
🔒 Security Target
Good Practice Documentation-first
Feed your SRS or BRD to generate requirement-traced tests
Upload your requirements document at the start of the project — before you write a single line of code. Gemini will extract all acceptance criteria, flag ambiguous or untestable requirements, and generate a traceability matrix so you always know which tests cover which spec items.
📄 Spec / PDF Target
Good Practice Before submission
Validate database constraints as part of your test suite
Missing foreign keys, nullable columns that shouldn't be, and absent unique constraints are silent data-integrity bugs. The Database Schema target catches these before they cause production incidents — especially important for Firebase/Firestore projects where schema is implicit.
🗄️ Database Target
